## 一、TLS 切换（P5-A1）

### 前置条件

1. [ ] 域名与解析：确认对外服务域名已解析到 124.70.107.64（当前仅裸 IP 访问；
       若继续用 IP，Let's Encrypt 无法签发，需购买 IP 证书或改用域名——**先拍板**）。
2. [ ] 华为云安全组放行 80/443 入方向（当前仅 8088）。
3. [ ] 服务器时间同步正常（证书校验依赖）：`timedatectl | grep synchronized`。

### 证书申请（推荐 Let's Encrypt，服务器出网约 5Mbps 可行）

```bash
# 方式一：standalone 临时占用 80（需先停 zhike_v2_frontend 或用 DNS 验证）
ssh <user>@124.70.107.64
certbot certonly --standalone -d <域名> --agree-tos -m <邮箱> --no-eff-email
# 产物：/etc/letsencrypt/live/<域名>/fullchain.pem + privkey.pem

# 方式二（有域名+已放行 80 时更平滑）：webroot 或 docker certbot，见 certbot 文档
```

### 部署证书与切换（scp 通道复用既有纪律：`-o UserKnownHostsFile=$HOME/.ssh/known_hosts`）

```bash
# 1. 证书入位（deploy/tls/certs/ 在服务器上对应 /data/zhike-v2/deploy/tls/certs/）
mkdir -p /data/zhike-v2/deploy/tls/certs
cp /etc/letsencrypt/live/<域名>/fullchain.pem /data/zhike-v2/deploy/tls/certs/
cp /etc/letsencrypt/live/<域名>/privkey.pem  /data/zhike-v2/deploy/tls/certs/
chmod 600 /data/zhike-v2/deploy/tls/certs/*.pem

# 2. 语法预检（切换前必做）
docker run --rm \
  -v /data/zhike-v2/deploy/nginx.https.conf:/etc/nginx/conf.d/default.conf:ro \
  -v /data/zhike-v2/deploy/tls/certs:/etc/nginx/certs:ro \
  nginx:1.25-alpine nginx -t
# 预期：syntax is ok / test is successful

# 3. 叠加 TLS 编排重建前端容器（后端不动，学习/考试会话不中断）
cd /data/zhike-v2/deploy
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d frontend

# 4. 环境变量核对（HTTPS 后建议开启，放行 D:\\... 前先确认反代已带 X-Forwarded-Proto）
grep -E "DJANGO_DEBUG|DJANGO_SECURE_SSL_REDIRECT|DJANGO_ALLOWED_HOSTS" .env.production
# 期望：DJANGO_DEBUG=false（已是）、DJANGO_SECURE_SSL_REDIRECT=True（本次改）、
#       DJANGO_ALLOWED_HOSTS 含服务域名（新域名时必须补）
# 改动后重建后端：
docker compose up -d --force-recreate backend
```

### 切换后验证命令

```bash
# 1. 明文跳转（应 301 → https）
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://<域名>/login
# 2. HTTPS 首页 200
curl -s -o /dev/null -w "%{http_code}\n" https://<域名>/
# 3. HSTS 头存在
curl -sI https://<域名>/ | grep -i strict-transport
# 4. API 经 HTTPS 反代可用（登录接口探活）
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://<域名>/api/auth/login/ \
  -H "Content-Type: application/json" -d '{"username":"__probe__","password":"__probe__"}'
# 预期 401（服务可达、失败锁定未触发）；401 而非 502/000 即链路通
# 5. 浏览器人工项：登录 → 上传附件 → 播放视频 → AI 问答各一次（静态资源混Content 警告检查）
```

### 回滚步骤（切换失败或异常时）

```bash
cd /data/zhike-v2/deploy
# 回到主线 HTTP 编排（8088:80）
docker compose -f docker-compose.yml up -d --force-recreate frontend
# 若已改 .env.production 的 SSL_REDIRECT，一并改回 False 并重建 backend
# 验证：curl -s -o /dev/null -w "%{http_code}\n" http://<IP>:8088/   # 预期 200
```

> ⚠️ HSTS 一旦上线且被浏览器记录，回滚后浏览器仍会强制 HTTPS 半年
> （`includeSubDomains` 作用于该域名）。**首次切换建议先以较小 max-age 试运行**
> （如 300s 观察 24h，再改 15768000），清单默认值按正式值写。

### 证书续期（切换完成后设置）

```bash
# Let's Encrypt 90 天有效；服务器加 cron：
echo '0 3 * * 1 certbot renew --quiet --deploy-hook "docker exec zhike_v2_frontend nginx -s reload"' \
  | sudo tee /etc/cron.d/certbot-renew
```

## 二、`/api/docs/` 生产关闭（P5-A3）

**无需操作**：代码已按 `API_DOCS_ENABLED = env_bool("DJANGO_ENABLE_API_DOCS", DEBUG)` 默认关闭
（生产 `DJANGO_DEBUG=false` → 404）。验证：

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<域名>/api/docs/    # 预期 404
curl -s -o /dev/null -w "%{http_code}\n" https://<域名>/api/schema/  # 预期 404
```

如需生产临时开放（排查联调），在 `.env.production` 加 `DJANGO_ENABLE_API_DOCS=true`
并重建后端，用完即关。
