Fixture 自动构造：管理员、教师A(t101)、**教师B（新建，其课程挂进 A 的同一个班）**、该班学生、备用学生、未挂班课程。

| 动作 | 管理员 | 教师A（授课） | 教师B（同班另一门课） | 学生 |
|---|---|---|---|---|
| 建班 `POST /api/classes/` | 201 | 403 | 403 | 403 |
| 改班 `PATCH /api/classes/{id}/` | 200 | 403 | 403 | 403 |
| 归档（`status=archived`） | 200 | 403/404 | 403/404 | 403/404 |
| 加成员 `add-student` | 200 | 403 | 403 | 403 |
| 移成员 `DELETE /api/class-students/{id}/` | 200 | 403 | 403 | 403 |
| 给班级挂自己的课 | 200 | 200 | 200 | 403 |
| 发作业 / 发考试 | 201 / 201 | 201 / 201 | 201 / 201 | 403 / 403 |
| 班级统计（不带 `course`） | 200（落 A 的课） | 200（落自己的课） | 200（落自己的课） | 403 |
| 班级统计 `?course=A的课` | 200 | 200 | **403** | 403 |
| 学生详情 `?course=A的课` | 200 | 200 | **403** | 403 |
| 邀请码加入 | 403 | 403 | 403 | **410** |

> 归档一行的 403/404 不是含糊：班级不在该教师可见范围时返回 404（不泄露存在性），

```python
qs.filter(
    classes__students__student=user,
    classes__students__learn_status__in=ClassStudent.OCCUPYING_STATUSES,
    classes__status__in=[ClassRoom.Status.ACTIVE, ClassRoom.Status.GRADUATED],
    status=Course.Status.ACTIVE,
```

## 7. 过程中发现并修复的真实缺陷

权限矩阵不是走过场——首轮 64 项里 2 项失败、后续又连带抓出 4 处，全部是**真缺陷**：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 矩阵「挂课 / teacher_a、teacher_b」403 | `ClassRoomViewSet` 整体套 `IsAdminOrReadOnly`，教师连挂自己的课都被挡 | `PATCH/PUT` 换 `IsTeacherOrAdmin` + `update` 里按字段白名单细分 |
| 2 | 班级统计「管理员 200」不成立 | `analytics` 五处视图 `permission_classes=[IsTeacher]`，而 `IsTeacher` **不含管理员** | 改 `IsTeacherOrAdmin`（导出/AI 报告/章节总结/学生详情一并放开） |
| 3 | 「发作业 / 发考试 管理员 200」不成立 | `IsTeacherOrReadOnly` 写分支只认 `is_teacher` | 写分支放开管理员（组织层补录教学数据的场景） |
| 4 | 教师挂课会**踢掉同班其他教师的课** | `_sync_courses` 是整体覆盖语义 | 新增 `courses_append` 上下文：教师挂课走追加，管理员仍是覆盖 |
| 5 | 督管班级行取不到建班人 | `AdminClassSerializer` 仍输出 `teacher_name/teacher_username`，而视图已改 `creator_name` | 序列化器改 `creator_*` + 补 `code`/`enrollment_year`/`duration_years`/`graduate_year`；CSV 导出列名同步 |
| 6 | 邀请码关闭后教师端仍展示邀请码 chip | 前端未同步下线 | 三端入口全部移除（§1.3） |

第 4 条是本期最有价值的发现：锚点迁移把一个班从「一个教师」变成「多教师共用」，
覆盖式挂课会静默删除别人的课，而**任何单角色测试都发现不了**——只有矩阵把教师A、教师B 放在同一个班上跑才暴露。
