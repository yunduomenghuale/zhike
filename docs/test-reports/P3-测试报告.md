## 4. 过程中发现并修复的缺陷

1. **教师挂课后接口回「旧清单」**（真缺陷，P3-4 暴露）
   `ClassRoomSerializer._sync_courses` 写入后没有清 `course_links` 的 prefetch 缓存，`to_representation` 读的是改动前的列表——教师刚挂上课，接口却回答「没挂上」，前端若拿响应渲染会静默回退。
   修复：写入后 `_prefetched_objects_cache.pop("course_links")`；加 6 项单测锁死（含追加语义、幂等、他人班 404、组织字段 403）。

2. **教师选班用错 HTTP 方法**（真缺陷）
   `updateClass` 是 PUT，只提交 `{courses:[...]}` 触发 400（缺必填字段），且带全量字段又会被后端的组织字段校验挡下。
   修复：`api/classroom.js` 增 `patchClass`，抽屉改走 PATCH。

3. **`include_questions` 用 `bool()` 解析字符串**
   multipart 提交 checkbox 时 `"false"` 会被判成 True，题库悄悄多复制一份。
   修复：`_as_bool()` 宽松解析（bool/数字/字符串）。

4. **复用权限最初借用了 `teacher_can_manage_course`**
   该函数放行平台管理员，但复用产物的 `Course.teacher` 必须落在真实教师账号上，管理员代建会产出「无主」课程。
   修复：`_reuse_denied` 只认课程创建者（教师），管理员 403 并有明确文案，已有测试覆盖。

5. **E2E 脚本自身两处断言写法错误**（非产品缺陷）
   - CSS `:hover` 无法用合成 `MouseEvent` 触发 → 改 CDP 真实 `Input.dispatchMouseEvent`；
   - Element Plus 的 `el-select` 选中值渲染在 `.el-select__selected-item`，不在 `input.value` → 改读容器 innerText。

## 6. 遗留与后续

- 复用产物为「停用」，教师需在课程列表手动启用；挂班仍走 P3-4 选班抽屉或管理员维护。
- 撤课（把课从班里摘掉）仍只支持管理员整体覆盖，教师端只做追加——与 P1「班级与课程的组织关系由学校统一维护」的边界一致。
- 开发库 `media/` 中积压的历史孤儿文件（约 1.4 GB，跨 lab_reports / question_imports 等目录，含 avatars 等非引用项）未在本次清理范围内，建议单独排期。
