### 1.3 关键实现决策

**单班不再靠巡检兜底，改用数据库条件唯一索引。**

```python
constraints = [
    models.UniqueConstraint(
        fields=["student"],
        condition=models.Q(learn_status__in=["active", "inactive"]),
        name="uniq_occupied_class_per_student",
    )
]
```

- `active` / `inactive` 占位，`transferred` / `removed` 是历史留痕不占位
- 被验证「真的落到了 DB 层」：单测 `test_direct_create_bypassing_service_is_blocked_by_db` 绕过 service 直接 create，断言抛 `IntegrityError`

**`User` 未新增 `classroom` 字段。** 核对 `apps/users/models.py` 证实该字段从不存在，v6 方案的「双表同步」整段建立在错误前提上。改为单一事实源 = `ClassStudent` 占用关系，避免同一事实两处存储。（详见方案 §5.2 与 v7 修订说明）

## 5. 过程中发现并修复的问题

### 5.1 前端两处硬编码绕过枚举改造（L3 抓出）

首轮 E2E 失败 2 项，都是**真实的 UI 缺陷**，不是测试写错：

1. `ClassManage.vue` 编辑弹窗的状态是 `el-radio-button value="open"` 硬编码 → 打开弹窗仍显示「开课中/已结课」
2. `AdminTeaching.vue` 行内状态下拉 `el-option value="open"` 硬编码 → 表格「状态」列直接显示原始值 `active`

修复：两处都改为遍历 `CLASS_STATUS_OPTIONS`。**教训已写入规范**：状态枚举改造不能只改渲染文案，必须全量搜索 `el-option` / `el-radio-button` 里的值。

### 5.2 旧后端进程占端口，导致接口 500（`no such column: courses_course.term`）

排查过程：迁移明明成功、表结构正确，接口却报旧列名 → 8005 被 15:02 启动的旧进程占着，新进程静默退出。终止旧进程后正常。
这与既有经验一致：**改 schema 后必须确认端口上跑的是新进程**，`--noreload` 也不会帮你重启旧的。

### 5.3 `User` 没有 `updated_at` 字段

`services.py` 里对 `User` 用 `save(update_fields=[..., "updated_at"])` 直接报 `ValueError`。`User` 继承 `AbstractUser` 而非 `BaseModel`，没有时间戳字段。已修正 3 处。

### 5.4 邀请码默认值推迟到 P1

方案 §4.1 写 `invite_enabled` 默认 `False`。若 P0 就改，会出现**新班无法入班、老班还能入班**的中间态。改为 P0 维持 `True`，P1 与「join 返回 410 + 前端移除入口」一起切换。
