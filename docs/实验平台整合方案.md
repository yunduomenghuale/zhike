# 实验平台功能整合方案

> 目标：将 `D:\Claude_Code\智课系统-实验平台`（计算机网络实验平台）中**有而本项目没有**的功能整合进智课系统V2。
> 原则：**能力移植，而非代码搬运**。实验平台是原生 Node.js + 静态 HTML + JSON 文件存储的技术栈，与本项目（Django 5 + DRF + Vue3）完全不同，直接搬代码会引入第二套运行时和第二套认证体系；正确做法是把**业务能力**按本项目约定（统一响应、BaseModelViewSet、access.py 行级过滤、JWT）重新实现。

```
┌────────────────────────── 智课系统V2（整合后） ──────────────────────────┐
│                                                                          │
│  Web 前端 (Vue3 + Element Plus)          移动端 (uni-app)                 │
│  ├─ 现有模块                                                             │
│  └─ ★新增: 实验中心 / 学习资源(导图+演示) / 数字人课堂                     │
│                                                                          │
│  Django 后端                                                              │
│  ├─ 现有 10 个 app                                                       │
│  ├─ ★新增 apps/labs     虚拟仿真实验(元数据/排课/报告/评分)                │
│  ├─ ★增强 apps/questions 主观题相似度评分并入 grading.py                  │
│  └─ ★增强 apps/knowledge 内容版本与审核(可选后期)                         │
│                                                                          │
│  静态资源: labs/*.html + demos/ + mindmap/  →  前端 public/ 或 nginx 子路径│
└──────────────────────────────────────────────────────────────────────────┘
```

**关键决策：实验页面以"静态资产 + 认证桥接"方式接入，而不是重写为 Vue 组件。**

理由：
- 7 个实验每个都是 1000+ 行的自包含 HTML（canvas 动画、终端模拟、步骤引擎高度耦合），重写为 Vue 成本极高且易引入回归；
- 实验页面本身已带步骤校验、评分、随机参数等全部前端逻辑，只需替换其**认证与数据上报层**（localStorage token → 本项目 JWT；`fetch(API_BASE/...)` → 本项目 `/api/labs/...`）；
- 静态 HTML 放入 nginx 子路径（如 `/labs/`），与本项目同域，用 postMessage 或 URL 携带短时票据完成免登。

## 三、后端修改方案（Django）

### 3.1 新增 app：`apps/labs`

**models.py**

```python
class Lab(BaseModel):
    """虚拟仿真实验元数据"""
    course = models.ForeignKey(Course, ...)          # 挂到现有课程体系
    code = models.SlugField(unique=True)             # 如 arp-ip-lab，对应静态页面目录名
    title = models.CharField(max_length=128)         # 实验二：ARP与IP子网综合实验
    description = models.TextField(blank=True)
    standard_minutes = models.PositiveIntegerField(default=30)  # 评分用标准时长
    max_step_score = models.PositiveIntegerField(default=100)   # 步骤满分
    order = models.PositiveIntegerField(default=0)

class LabSchedule(BaseModel):
    """实验排课与开放时间（对应 lab-schedules）"""
    lab = models.ForeignKey(Lab, ...)
    classroom = models.ForeignKey(CourseClass, ...)  # 对应班级
    open_at = models.DateTimeField()
    close_at = models.DateTimeField()
    allow_retry = models.BooleanField(default=True)

class LabAttempt(BaseModel):
    """学生一次实验作答（提交时创建，防作弊留痕）"""
    lab = models.ForeignKey(Lab, ...)
    student = models.ForeignKey(User, ...)
    schedule = models.ForeignKey(LabSchedule, null=True, ...)
    random_seed = models.JSONField(default=dict)     # 本次随机参数（IP网段等），提交时校验一致性
    base_score / accuracy_score / efficiency_score / completion_score / total_score
    error_count / elapsed_seconds / passed_steps / total_steps
    error_log = models.JSONField(default=list)       # 每步错误命令记录
    status = choices(submitted / reviewing / returned)

class LabReport(BaseModel):
    """实验报告（DOCX/PDF 生成结果）"""
    attempt = models.OneToOneField(LabAttempt, ...)
    conclusion = models.TextField()                  # 学生结论（前端禁粘贴）
    docx_file = models.FileField(...)                # 存 media/
    pdf_file = models.FileField(...)
```

**views.py（BaseModelViewSet + api_response，遵循现有约定）**

```
GET  /api/labs/                          学生：可见实验列表（按班级排课过滤，access.py 行级过滤）
GET  /api/labs/{id}/schedule/            该实验对当前用户的开放窗口
POST /api/labs/{id}/attempts/            开始实验 → 下发随机参数种子（服务端生成并记录）
POST /api/labs/{id}/attempts/{aid}/submit/  提交评分结果（分数由服务端按同一规则重算，不信任前端）
GET  /api/labs/{id}/reports/mine/        我的报告列表
POST /api/labs/{id}/attempts/{aid}/conclusion/  提交结论并触发生成报告
GET  /api/lab-reports/{rid}/download/?format=docx|pdf
教师端:
GET  /api/labs/{id}/attempts/            按班级查看全部成绩与错误日志
POST /api/labs/attempts/{aid}/review/    复核/调整分数
CRUD /api/lab-schedules/                 排课管理
```

**评分规则移植（labs/scoring.py）**：把 `lab-scoring-enhance.js` 的规则在服务端复刻为唯一真相源：

```python
def calc_final_score(step_score, max_step_score, passed, total, error_count, elapsed_min, standard_min=30):
    base = round(step_score * 0.8)
    accuracy = max(0, 5 - error_count)
    efficiency = max(0, 5 - max(0, elapsed_min - standard_min) // 3)
    completion = round(passed / total * 10) if total else 0
    return {"base": base, "accuracy": accuracy, "efficiency": efficiency,
            "completion": completion, "total": base + accuracy + efficiency + completion}
```

报告生成用 `python-docx` + `reportlab`（或 weasyprint），模板还原实验平台报告版式（实验名/学生/班级/日期/步骤清单/评分明细/结论）。

### 3.2 增强 `apps/questions/grading.py`：主观题相似度评分

把 `quiz-api-router.js` 的算法移植为 `grade_subjective(user_answer, correct_answer, qtype)`：

```python
STOP_WORDS = {"的", "是", "在", "了", "和", "与", "或", ...}  # 中文停用词

def levenshtein(s1, s2): ...          # 动态规划
def string_similarity(s1, s2): ...    # 1 - dist/maxlen
def keyword_match_ratio(user, correct): ...  # 关键词（去停用词）命中率
def fill_similarity(user, correct): ...      # 填空：多答案任一匹配 + 归一化文本比对

def grade_subjective(user_answer, correct_answer, qtype):
    sim = fill_similarity(...) if qtype == "fill" else 0.7 * keyword_match_ratio(...) + 0.3 * string_similarity(...)
    if sim < 0.3:   score, verdict = 0.0, "wrong"
    elif sim >= 0.9: score, verdict = 1.0, "correct"
    else:           score, verdict = sim, "pending_review"   # 触发教师复核流
```

接入点：
- 作业提交链路：主观题先自动预评分，`pending_review` 的进入现有教师批阅队列（复用 correct_status 流转）；
- 考试主观题：同样先给出 AI 预评分 + 置信标记，教师复核时可见参考分，降低批改工作量。

### 3.3 增强 `apps/knowledge`（可选，后期）

- `KnowledgeMaterial` 增加版本字段 + 版本快照表（回滚能力）；
- AI 生成内容先进 `pending` 状态，教师 approve/reject 后才对学生可见（对应 kb-review-manager）。

## 四、前端与静态资产接入方案

### 4.1 实验页面（labs/*.html）

1. **资产放置**：7 个实验 HTML 及其依赖复制到 `deploy` 挂载的静态目录，nginx 配置 `location /labs/`（与 `/m/` 子路径同模式），或放 `frontend/public/labs/` 由 Vite 打包分发。
2. **认证桥接（免登）**：
   - 学生在 Vue 端点击"进入实验"→ 前端先调 `POST /api/labs/{id}/attempts/` 拿到 `attempt_id + attempt_token`（短时效一次性票据）；
   - 跳转 `/labs/arp-ip-lab.html?attempt=xxx&token=xxx`；
   - 实验页内改造一个统一的 `lab-bridge.js`（替代原 auth-check.js/api-client.js）：
     - 用 token 调本项目 API 上报步骤结果/错误日志；
     - 顶部条显示"返回课程"链接；
     - 提交时调 `submit` 接口，由服务端重算分数。
3. **随机参数防作弊**：原页面 `Math.random()` 生成网段 → 改为从 URL 票据换取服务端下发的种子参数，提交时服务端校验结果与种子一致。

### 4.2 思维导图 / 演示（mindmap/ + demos/）

- 作为"学习资源"挂到课程章节：`Course`/章节模型增加 `resources`（类型：mindmap/demo，指向静态路径），教师可在建课时从资源库勾选；
- 页面同样接入 `lab-bridge.js` 式的轻量桥接（仅注入 JWT + 可选学习时长上报，复用现有 analytics 埋点）；
- markmap 是 CDN 引用，需把 markmap 的 js/css 下载到本地静态目录，避免生产环境外网依赖。

### 4.3 数字人视频课堂

- 不新建 app，放入 `apps/courses`：新增 `CourseVideo(BaseModel)`（course/chapter 外键、title、video 文件、description）；
- 上传走 Django FileField（≤500MB 校验），播放用 nginx `sendfile` + Range（现有 media 静态服务已支持）；
- 教师端：课程详情页加"数字人视频"管理 Tab；学生端：章节内视频卡片。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 实验 HTML 与桥接层耦合改造成本被低估 | 先改造 1 个实验（arp-ip）跑通全链路，再批量套用；STEPS/evalFn 逻辑不动 |

## 八、总结

- **直接移植算法**：主观题相似度评分 → `questions/grading.py`；实验评分规则 → `labs/scoring.py`（服务端为唯一真相源）；
- **新建 Django app**：`labs`（实验/排课/作答/报告），完整复用现有认证、权限、行级过滤、统一响应约定；
- **静态资产桥接**：7 个实验页面 + 思维导图 + demos 原样保留前端逻辑，通过一次性票据免登接入本项目；
- **轻量增强现有 app**：数字人视频并入 courses，知识库治理后期并入 knowledge；
- **不动实验平台前端核心逻辑**（STEPS 步骤引擎、canvas 动画、终端模拟），只替换其认证与数据层，控制改造成本与回归风险。
