# 管理端督管能力增强 · 开发方案

> 配套文档：《docs/管理端督管能力架构分析.md》
> 方案时间：2026-10-19 ｜ 基线：Django 5 + DRF + SQLite / Vue 3 + Element Plus
> 原则：**复用优先、读多写少、全程审计、不引入新依赖**

---

## 0. 方案总览

### 0.1 目标（逐条对应痛点）

| 用户痛点 | 方案落点 |
|---|---|
| 只能看到数量 | 概览加趋势序列 + 环比；监管表格加内容资产/进度/活跃度列 |
| 看不到具体内容 | 课程/班级/教师三个详情抽屉（复用教师端聚合逻辑） |
| 不能执行基础管理功能 | 班级结课/开课干预、批量导出、操作审计查询 |
| （衍生）干预无痕迹 | `AdminActionLog` 覆盖全部管理端写操作 |

### 0.2 范围

- **做**：平台级聚合读服务、9 个新端点、1 个新模型（审计）、3 个新组件、2 个页面重构、1 个新页面（操作审计）。
- **不做**（明示边界）：管理员写教学过程数据（成绩/提交/题目）、删除类操作、引入 ECharts 等新依赖、重构存量 API 风格、定时汇总表（数据量未到）。

### 0.3 分期

| 阶段 | 内容 | 预估 |
|---|---|---|
| **一期（P0）** | 审计模型 + 全部写操作埋点 + 审计查询页；课程/班级详情抽屉；概览 alerts + trends | 3~4 天 |
| **二期（P1）** | 教师维度 tab + 详情；三个维度 CSV 导出；班级状态干预（开课/结课） | 2 天 |
| **三期（P2）** | 概览指标环比卡片、DAU 趋势、throttle、按需缓存 | 1~2 天 |

## 1. 架构决策（先定规矩，再写代码）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 督管权限边界定为「**全局只读 + 白名单干预 + 全程审计**」。白名单仅：课程状态、班级状态、账号管理、AI 配置、向量重建 | 与需求文档定位衔接；教学过程数据（成绩/提交）对管理员只读，守住 `common/access.py` 的行级模型 |
| D2 | 聚合逻辑收敛到 **`apps/analytics/services.py`**（该 app 本就是"纯聚合其它模块数据"），平台端复用同一函数，**禁止在 platform_admin 重写统计** | 避免双份维护漂移；`build_class_stats` 本就不感知用户，权限在 view 层，天然可复用 |
| D3 | 审计模型放 **`apps/platform_admin/models.py`**（新建），继承 `common.models.BaseModel` | platform_admin 目前无 models.py，正好以审计表作为首个模型；不与业务库耦合 |
| D4 | 图表用**自研 SVG 折线组件**（`frontend/src/components/charts/TrendChart.vue`，约 120 行，light 主题），**不引 ECharts** | 全站当前无图表库，引入 = 新依赖 + 打包体积 + 构建链变化；督管趋势图信息密度低，SVG 足够 |
| D5 | 新端点沿用 platform_admin 现有 `APIView + _paginated_response` 内部风格，**不重构存量** | 控制改动面；风格统一（ViewSet 化）单独立项 |
| D6 | 所有干预动作走「**影响预览 → 二次确认 → 执行 → 审计**」四步 | 跨租户写必须可预期、可追溯 |

## 2. 后端设计

### 2.1 新增模型与迁移

**`apps/platform_admin/models.py`（新建）**

```python
class AdminActionLog(BaseModel):
    class Action(models.TextChoices):
        COURSE_STATUS = "course_status", "课程状态变更"
        CLASS_STATUS = "class_status", "班级状态变更"
        USER_CREATE = "user_create", "创建账号"
        USER_UPDATE = "user_update", "编辑账号"
        USER_RESET_PWD = "user_reset_pwd", "重置密码"
        USER_IMPORT = "user_import", "批量导入账号"
        AI_CONFIG_SAVE = "ai_config_save", "保存AI配置"
        AI_CONFIG_TEST = "ai_config_test", "AI连接测试"
        VECTOR_REBUILD = "vector_rebuild", "重建向量库"

    actor = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.PROTECT,
                              related_name="admin_actions", verbose_name="操作人")
    action = models.CharField("动作", max_length=32, choices=Action.choices)
    target_type = models.CharField("对象类型", max_length=32)      # course / class / user / ai_config ...
    target_id = models.IntegerField("对象ID", null=True, blank=True)
    target_label = models.CharField("对象名称", max_length=200, blank=True)
    old_value = models.JSONField("变更前", null=True, blank=True)
    new_value = models.JSONField("变更后", null=True, blank=True)
    note = models.CharField("备注", max_length=255, blank=True)

    class Meta:
        verbose_name = "管理端操作审计"
        ordering = ["-id"]
        indexes = [models.Index(fields=["-created_at"]), models.Index(fields=["action", "-id"])]
```

**迁移**：`platform_admin/migrations/0001_initial.py`（新建 migrations 包）。纯新增表，无存量数据变更，SQLite 下零风险；若后续要 target 改唯一约束，按项目先例（courses/0010）走两步迁移，本期不需要。

**审计写入 helper（`platform_admin/audit.py`）**：

```python
@contextmanager
def audit_action(actor, action, target_type, target_id="", target_label="",
                 old_value=None, new_value=None, note=""):
    """with audit_action(...) 包裹写操作；仅请求成功时落库（配合 view 返回前调用 commit）。"""
```

实现要点：view 内显式调用 `log_admin_action(request, action=..., ...)`（请求结束后、响应 2xx 时写）。失败请求不写——helper 内部判断 `response.status_code < 300`。为控制一期改动面，采用「view 内显式调用」而非 middleware 全自动（AI 配置的字段级 diff 已有 AICapabilityChangeLog，本期保持双轨，二期再合并）。

### 2.2 聚合服务层

**`apps/analytics/services.py`（新建，从 views.py 平移）**

**`apps/platform_admin/services.py`（新建）**

| 函数 | 说明 |
|---|---|
| `platform_trends(days)` | 日粒度序列：`new_users / new_courses / new_classes / active_students`（DAU = VideoWatchProgress.updated_at 去重 UNION AnswerRecord.submitted_at 去重，本地时区分组）。**性能护栏：days ≤ 90**；单次 TruncDate 分组查询 + Python 补零 |
| `platform_alerts()` | 待办与异常：待批改作业提交数（HomeworkSubmission.correct_status=submitted）、成绩未发布考试数（Exam.score_released=False 且 status∈(published,finished)）、AI 近 24h 失败率与 Mock 回退（复用 `views._alerts` 同款计算，抽到 services 共享）、解析失败课件数（PPTResource.parse_status=failed）、14 天未登录教师数（User.last_login）、14 天无学习记录班级数。每项带 `count + jump_url` |
| `course_overview_counts()` | 课程列表 annotate：catalog_count、ppt_count（PPTResource）、question_count、video_count、active_homework、active_exam、last_content_update（取 Catalog/PPTResource/Question 的 updated_at 最大值） |
| `class_overview_counts()` | 班级列表 annotate：course_count、student_count + **学习进度汇总**（复用 build_class_stats 的 summary 维度：作业提交率/考试完成率/预警人数）——按班级循环调用一次聚合，**页大小 10，N+10 次查询可接受**；超过 50 条的导出场景改为轻量聚合版（只算比率不算逐人明细） |
| `teacher_overview_rows()` | 教师维度：课程数、班级数、学生数、AI 调用次数/tokens（AICallLog.triggered_by）、最近活跃（max(last_login, 内容 updated_at)） |

## 5. 兼容与迁移

- **零破坏性**：A3/A8 为响应增字段（前端旧缓存无感知，刷新即得）；A5 为响应增字段；无端点删除、无字段语义变更。
- **数据库**：仅新增 1 张表（platform_admin 0001）。SQLite 新建表无重建风险。
- **回滚**：`migrate platform_admin 0001` 前状态即可（删表）；前端回滚 = 还原 3 个 vue + api/admin.js + router。
- **部署**（按项目现有流程）：后端改动 → 生产 `docker compose build backend`（层缓存）；前端 → 源码 `npm run build` 后 scp dist（分批 ≤30 文件 + sleep 5 的既定策略）；本次两处都动，按先 backend 后 frontend 顺序。

## 7. 性能与安全护栏

- **查询护栏**：trends days ≤ 90；导出 ≤ 5000 行；班级统计循环查询仅限分页内（≤10）；DAO 口径注释写明降级路径（数据量上来后改登录口径/汇总表）。
- **索引**：AdminActionLog 建 `-created_at`、`action+-id` 复合索引；trends 依赖 `date_joined/created_at`（BaseModel 无索引但 SQLite 小表可接受，PG 迁移时补）。
- **安全**：新端点统一 IsPlatformAdmin；导出同 AI 流水的窗口校验模式；审计表 `actor` 用 PROTECT 防误删用户连带丢审计。
- **P2/P3 待办（2026-10-19 全部完成）**：管理端 throttle（分档限流 + 429 本地化 + 测试隔离）、overview 缓存（trends/alerts 60s 文件缓存，跨 worker 一致）、审计与 AICapabilityChangeLog 合并（单一审计轨：AdminActionLog.ai_config_save 存按能力分组字段级 diff，存量经迁移 ai/0010 回填，旧表/端点保留仅查历史）、ViewSet 风格统一（课程/班级/教师/审计四组同资源多端点收口为 ViewSet，URL 逐条显式映射不变；单方法端点与存量 APIView 保留，理由见代码注释）。
- §9 四个待产品确认项已按默认值落地（白名单不含删除 / 14 天 / AI 消耗平台管理员可见 / 审计含 admin 自身）。

## 8. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 班级统计 N+10 查询拖慢监管列表 | 中 | 页大小 10 封顶；列表只取 summary 比率（不走逐人明细）；导出用轻量聚合版 |
