## 一、目标与边界

现有 `apps/labs` 只支持「教师从 7 个平台预置模板里选一个」，教师无法上传自己的实验。本方案在**现有 labs 上扩展**（不新建 app、不改师生端入口）：

1. 教师自建实验：填标题、课程、总分等基本信息，**上传一个交互 HTML 单文件**（→ 预留 ZIP 资源包扩展位）；
2. 教师创建实验后，系统给出**成绩上报接口地址 + 按实验参数动态生成的接入说明（一键复制给 AI 编程工具）+ 在线调试**；
3. HTML 页面在**沙箱 iframe**（opaque origin）内实现步骤判分（逻辑清晰、完成即出分），调 `LabBridge.reportGrade()`；由**平台父页面**代发 POST 到成绩上报端点——页面本身读不到票据、也发不了同源请求；
4. 平台校验身份与范围后，服务端补上提交时间入库，**提交即完成实验**，学生立刻看到分数；
5. 身份鉴别与防刷分取极简档（见第八节）。

**关键简化**：平台**不要求教师填步骤清单、不接收步骤明细**。步骤名称、每步分值、判分规则全部由 HTML 自己掌握，平台只认一个总分。这样教师不必把同一份信息填两遍，AI 生成页面时也不受平台配置约束。

**明确不做**：

- 教师另部署评分服务、平台代理外呼、任何服务端对外部 HTTP 的调用（因此**无 SSRF 面、无出网要求、无超时/并发闸门**）；
- `step_config` 步骤清单、步骤 key 校验、`sum(steps) == total_score` 一致性校验（v2 设计，v3 删除）；
- 结构/一致性防刷、**最短用时拒答**、服务端按规则复算分数（**异常标记 S5 改为「只标记不拒答」，已纳入 v3.1**）；
- 教师手动评分（manual）模式与「待评分」状态；
- 实验模板跨教师共享、ZIP 解压、移动端答题；
- **仿冒 UI / 页面内钓鱼的治理与缓解机制**（用户 16:00 判定为教师上传方责任，不属本期范围）。

## 二、架构决策：甲

「成绩接口」曾有歧义，最终锁定**甲：系统提供成绩上报接口**。乙（教师部署评分服务 + 平台代理外呼）已作废。

用户业务事实（已确认）：自定义实验**没有仿真计算环节**，步骤判分机制清晰、完成即出分；平台机房只能内网访问，靠**端口映射 + 域名**对外提供服务（入站通道）。甲方案天然走这条通道，学生能打开实验页就能提交成绩，**机房不需要主动出公网，不需要公网 IP/域名给教师侧，不需要 CORS/https 证书**。

上报就是一次同源 POST（**v3.2 下由平台父页面 `lab-bridge-parent.js` 代发**，教师 HTML 只经 `postMessage` 传分数），毫秒级。

## 五、后端改动

### 5.1 成绩上报端点（新增，核心）

`POST /api/lab-gate/grade/`（显式 `path()`，**必须写在 `router.urls` 之前**；DRF `APIView`，复用认证/限流/统一响应）

- 认证：`authentication_classes = [LabTokenAuthentication]`，请求头 `X-Lab-Token`。**v3.2/L2**：该头只由**平台父页面** `lab-bridge-parent.js` 附加；iframe 内 shim 无票据，且 opaque origin 下发带自定义头的同源请求会触发 CORS 预检（C42），双重保证教师页面无法直接调用本端点
- 权限：`IsStudent` + `student_submit_block_detail()`（提交类学籍门控）
- 限流：新增 `lab_grade` scope（**同时**写 `GLOBAL_THROTTLE_RATES` 与 `DEFAULT_THROTTLE_RATES`），自定义 throttle 实现 `get_cache_key` 按 `user.pk`
- **服务端从票据反查 `submission` / `lab`**，不接受请求体指定实验 id 或学生身份

请求体（**只有两个字段**）：

```json
{ "total_score": 86.5, "elapsed_seconds": 742 }
```

**`submitted_at` 由服务端 `timezone.now()` 写入，页面不传、传了也忽略**（浏览器时间学生可改，若采信就等于没有截止时间）。**S1：落库的 `elapsed_seconds` 一律由服务端按 `submitted_at - started_at` 计算**（`started_at`/`submitted_at`/`elapsed_seconds` 三列在 `models.py:156,175-176` 已存在，**零迁移**）；页面传来的 `elapsed_seconds` 只写进 `grade_raw` 留痕、不采信、不参与任何判定。票据 2h TTL 天然给用时封顶。

**在 `transaction.atomic()` 内按序执行（S2/S3）**，任一失败抛 `ValidationError`，统一 `{code,message,data}`：

0. **S2 双行锁**：`select_for_update()` 同时锁 `LabSubmission`（`pk=ticket.submission_id`）与 `LabAttemptToken`（`pk=ticket.pk`），**锁后重新读取并复验以下全部条件**。现有 `submit` 的 `get_object()` 与 `bridge.validate_token()` 都无锁，两个并发请求可同时通过 `in_progress` 检查（C31）。
1. 票据存在 / 未消费 / 未过期。**不写 `ticket.student_id == request.user.id` 这种伪校验**——`LabTokenAuthentication` 把 `request.user` 直接设成 `ticket.student`（`auth.py:27`），该比较恒为**真**（等于没校验），`bridge_validate` 里同款代码是自我抵消的（C32；最后一轮复核更正：v3.1 误写为「恒假」，结论不变）。身份鉴别靠「持有票据本身 + 服务端从票据反查 submission/lab」，并校验 `ticket.student_id == ticket.submission.student_id` 防数据被改。
2. `ticket.submission.status == 'in_progress'`，且 `lab.page_source == 'custom'`、`lab.status == 'published'`、排课窗口 `schedule.is_open()` **三者同时成立**（`bridge_validate` 只验发布状态、不验窗口，`views.py:330`；`start`/`submit` 才验窗口 → 新端点必须补齐，C32）。
3. 学籍门控 `student_submit_block_detail(request.user, "提交实验成绩")`。
4. `total_score` 可转 1 位小数，`0 ≤ total_score ≤ lab.total_score`。
5. 报文序列化后 ≤64KB；客户端 `elapsed_seconds` 为非负数（不设下限、不拒答，但按 S1 不采信）。

入库（**同一个 `transaction.atomic()`**，与现有 `submit` 同构）：写 `status='submitted'`、服务端生成的 `submitted_at`、**S1 服务端计算的 `elapsed_seconds`**、`total_score`、`score_breakdown`（含 `total`/`source`/`elapsed_seconds`）、`grading_source='external'`、`grade_raw`（请求体原文 + 服务端上下文）、`grade_raw_digest`、`graded_at`；**`consume_token(ticket)` 必须放进同一事务内**（现放在事务外，进程崩溃会留下可重放的未消费票据，C31）；**S5** 若 `total_score == lab.total_score` 且服务端用时 < `min(60, standard_minutes*60*0.1)` 秒，则置 `abnormal=True` 并在 `grade_raw` 记原因，**只标记不拒答**——`abnormal` / `reviewed` / `reviewed_by` / `reviewed_at` 四列 `models.py:168-174` 均已存在，零迁移。任一环节失败整事务回滚、票据仍有效，学生可直接重试，无需中间态、无需队列。

> 建议把「写状态 + 分数 + 消费票据」抽成 `apps/labs/services.py::finalize_submission()`，现有 `submit` 与新增上报端点共用，保证状态机唯一、不漂移。

> **C45（最后检查新增）**：v3.1 的 `inject_bridge(html, base)` 是单桥接签名，无法表达 L2 三分流；父页面模板**必须自带 `<base>`**（指向 `gate.asset_base()` 的签名资产路由），否则 `<script src="lab-bridge-parent.js">` 会解析到 `/api/lab-gate/page/{token}/lab-bridge-parent.js` 而 404。父页面占位符 `__FRAME_URL__` / `__LAB_BOOT_TOKEN__` / `__LAB_CONTEXT__` / `__LAB_PREVIEW__` 由 `render_parent()` 做字符串替换（**不用 Django 模板**，避免与教师 HTML 混淆）；iframe 的 `src` 必须写**绝对路径** `/api/lab-gate/frame/...`，否则会被 `<base>` 改写到资产路由。

**注入点必须是 `<head>` 之后，不能是 `</body>` 之前**：7 个预置页都在第 7 行 `<script src="lab-bridge.js">`，页面内联脚本依赖 `window.LabBridge` 已就绪。同时：

- 用 `/<script[^>]+src=["'][^"']*lab-bridge[^"']*\.js/` 预检，**已存在则跳过**（否则 IIFE 双跑 → 重复提交）；
- **S7 三分流（v3.2）**：① `page_source=template` → 沿用 `lab-bridge.js`（7 个预置页本体已引用，注入跳过，`tests.py:212` 断言的 `<script src="lab-bridge.js">` 子串不变）；② **custom 的 iframe 内容页** → 注入 `<script src="lab-bridge-shim.js"></script>`（**无票据 shim**，只做 `postMessage`）；③ **custom 的平台父页面** → 注入 `<script src="lab-bridge-parent.js"></script>`（**持票据、真正发上报请求**）。`lab-bridge.js` 一行不改，`tests.py` / `e2e_real_test.py` 零回归（C27）；
- 引导脚本（把票据交给**父页面**桥接 IIFE）只注入父页面，**绝不注入 iframe 内容页**；父页面入口是 `no-store`，资产路由是 `private, max-age=7200`，**票据绝不能进资产脚本**（C30）；
- `inject_base` 需先剥掉 HTML 里已有的 `<base ...>`：`resource_gate.inject_base` 只插不去重，两个 `<base>` 时浏览器取第一个 → 签名 base 失效 → 桥接脚本 404。iframe 内 `<base>` 仍指向签名资产路由——**经典 `<script>` / `<link>` / `<img>` 跨源加载不受 CORS 限制，可用；但 iframe 内不能发带自定义头的同源 fetch**（C42）。

### 5.5 L2 双桥接：父页面持票据 + iframe 内无票据 shim

**C27 核实结论**：不能直接改现有 `lab-bridge.js`。它 `:25` 从 `location.search` 读 `?token=`、`:117` 把整个对象（含 `token`）挂到 `window.LabBridge`，7 个预置实验与 `tests.py` / `e2e_real_test.py:179` 全依赖它。因此：

- `deploy/labs/lab-bridge.js`：**保持原样**，只服务 7 个预置实验；
- `deploy/labs/lab-gate-parent.html`（**新增**）：平台父页面模板，含 `sandbox` iframe 与 `__FRAME_URL__` / `__LAB_BOOT_TOKEN__` / `__LAB_CONTEXT__` / `__LAB_PREVIEW__` 四个占位符，由 `render_parent()` 替换；**自身也要注入 `<base>`**（C45）；
- `deploy/labs/lab-bridge-parent.js`（**新增**）：父页面持票据桥接，**唯一**能发 `X-Lab-Token` 的脚本；
- `deploy/labs/lab-bridge-shim.js`（**新增**）：iframe 内 shim，**无任何票据**，对教师 HTML 暴露兼容的 `window.LabBridge`。

**（1）父页面 `lab-bridge-parent.js`**

```js
(function (bootToken) {
  'use strict';
  var token = bootToken, reported = false;
  delete window.__LAB_BOOT_TOKEN__;
  var frame = document.getElementById('lab-frame');
  window.addEventListener('message', function (e) {
    if (e.source !== frame.contentWindow) return;         // C41：不能只靠 event.origin
    var m = e.data || {};
    if (m.type === 'lab:context') {                       // 只回传非敏感 context
      e.source.postMessage({ type: 'lab:context:result', context: window.__LAB_CONTEXT__ }, '*');
      return;
    }
    if (m.type !== 'lab:grade' || reported) return;       // S4 一次性闸门
    reported = true;
    fetch('/api/lab-gate/grade/', {
      method: 'POST', credentials: 'same-origin',
      headers: { 'Content-Type': 'application/json', 'X-Lab-Token': token },
      body: JSON.stringify(m.payload || {})
    }).then(function (r) { return r.json(); }).then(function (res) {
      if (res.code !== 0) reported = false;               // 失败可重试
      e.source.postMessage({ type: 'lab:grade:result', response: res }, '*');
    }).catch(function () { reported = false; });
  });
})(window.__LAB_BOOT_TOKEN__);
```

**（2）iframe 内 `lab-bridge-shim.js`**（opaque origin，无票据、不能 fetch）

```js
(function () {
  'use strict';
  var pending = {};
  window.addEventListener('message', function (e) {
    var m = e.data || {}, p;
    if (m.type === 'lab:context:result' || m.type === 'lab:grade:result') {
      p = pending[m.type]; if (p) { delete pending[m.type]; p(m); }
    }
  });
  function ask(type, extra) {
    return new Promise(function (resolve) {
      pending[type === 'lab:context' ? 'lab:context:result' : 'lab:grade:result'] = resolve;
      window.parent.postMessage(Object.assign({ type: type }, extra || {}), '*');
    });
  }
  window.LabBridge = {
    preview: window.__LAB_PREVIEW__ === true,
    context: null,
    validate: function () {
      return ask('lab:context').then(function (m) {
        this.context = m.context; return m.context;
      }.bind(window.LabBridge));
    },
    reportGrade: function (payload) {
      return ask('lab:grade', { payload: payload }).then(function (m) { return m.response; });
    }
  };
})();
```

**契约要点**：

- `postMessage` **只传 context 与分数/响应，绝不传票据**；目标 origin 用 `'*'`（opaque origin 下 iframe 的 `event.origin` 是字符串 `"null"`），安全性靠父页面校验 `event.source === frame.contentWindow`（C41）。
- 票据只存在于父页面 IIFE 闭包；**教师 HTML 无论编写时还是运行时都拿不到**，**C25 就此真正解决**。
- `context` 由父页面用票据调 `GET /api/labs/bridge-validate/?token=<attempt_token>` 取回，再**映射成 `{labId, submissionId, totalScore, gradeEndpoint}` 四字段**写入 `window.__LAB_CONTEXT__`；`bridge_validate` 原响应里的 `random_seed` / `expected` / `status` **一律不透给 iframe**（C45）。`totalScore` 取 `lab.total_score`，`gradeEndpoint` 固定 `/api/lab-gate/grade/`。预览模式不调该接口，用本地 mock context。
- iframe 内**不能发带自定义头的同源 fetch**（opaque origin 下触发 CORS 预检，C42），分数只能走 `postMessage`；`<script src>` 跨源加载 shim 不受 CORS 限制，可用。
- 学生在**自己会话的父页面**里仍可从查看源码 / 网络面板看到自己本次票据（残余风险 D，用户已接受）；这与「教师 HTML 拿不到票据」是两回事，不要混为一谈。

**（3）对教师 HTML 与 AI 指令的兼容性**：`LabBridge.validate()` / `context.totalScore` / `reportGrade({total_score, elapsed_seconds})` / `LabBridge.preview` **四个 API 完全不变**，最简示例与 AI 指令无需改调用方式；只需在接入说明补「页面运行在沙箱 iframe 内」的运行限制（对接说明 §七）。

`preview=1` 时父页面不注入票据、shim 的 `LabBridge.preview = true`，`validate()` 返回本地 mock context、不提交。

> 三个新文件都在 `:ro` bind mount（`./labs:/app/labs:ro`），同步到 `/data/zhike-v2/deploy/labs/` 即生效；**但 `urls.py` 新增 frame 路由与 `views.py` 分流属于后端代码改动，仍需 `compose build backend`（C43）**。

完整规格见 `docs/实验管理-自定义实验对接说明.md`（给 AI 编程 agent 直接复制的版本）。要点：

1. 时序：学生进实验 → 平台父页面（持票据）+ `sandbox` iframe（教师 HTML）→ iframe 内 `lab-bridge-shim.js` 提供 `window.LabBridge` → `validate()` 经 `postMessage` 拿 `context.totalScore` → 页面内步骤判分 → `reportGrade()` 经 `postMessage` 交父页面 → **父页面代发 POST** → 平台入库即完成
2. 请求：`POST /api/lab-gate/grade/`，`Content-Type: application/json`；`X-Lab-Token` **只由平台父页面**的 `lab-bridge-parent.js` 附加（票据从不进 iframe / 教师 HTML / `LabBridge`）；**同源，无需 CORS / https 特殊配置 / 公网 IP 或域名 / 独立源 / DNS**
3. 请求体：`{"total_score": 86.5, "elapsed_seconds": 742}`；**提交时间与正式用时均由服务端生成/计算，页面值只留痕**
4. 响应：`{code:0, message:"成绩已提交", data:{submission_id, total_score, status:"submitted", submitted_at, graded_at}}`
5. 约束：`0 ≤ total_score ≤ 实验总分`（1 位小数）、页面 `elapsed_seconds ≥ 0`、报文 ≤64KB；**落库用时以服务端 `submitted_at - started_at` 为准**
6. 页面写法：单 HTML 内联全部 JS/CSS，禁止相对路径外部资源（`<base>` 已指向签名资产路由）

**诚实的上限（必须写进对接说明）**：判分规则在前端 HTML 里，且平台不再做结构/一致性校验。学生只要正常进入一次实验，就能在 DevTools 里直接调桥接方法或复制请求报一个满分；懂行学生改写页面 JS 更不在话下。极简档挡的是「无学籍/无票据直接 POST」「重复提交与重放」「越界分数」「伪造提交时间」，**挡不住伪造满分**。v3.1 的 S1–S8 加固**同样没有改变这个上限**；它们解决的是并发、时间、窗口、CSP 与审计问题，并额外暴露出一项此前遗漏的同源 HTML 风险（§八·补 8.4 A）。

**已评估并明确否决的两个加码方案（本期不做）**：

| 方案 | 否决理由 |
| --- | --- |
| JS 加密 / HMAC 签名 / 代码混淆 | 密钥必须下发到浏览器，学生从源码即可取得；`CryptoKey.extractable=false` 只防导出密钥、不防调用 `sign()` 签任意内容；只能挡顺手作弊，还给虚假安全感 |
| 服务端复算（AI 内嵌判分规则、教师零填报） | 唯一能真正防死的方案，但要页面改报 `answers`、后端加规则解析与复算、规则表达力受限于结构化实验；与本期「极简」取舍不符，留作计分/高利害实验的后续选项 |

> **v3.2 更正**：「父页面 + `sandbox` iframe 托管票据」原被列为否决项（当时的目标是**防刷分**，DevTools 仍能调桥接，故判无效）；A 风险专项换成「**隔离不可信 HTML**」这个目标后，用户已拍板采纳为**正式架构**（§5.5 / §8.3 D 档 / §8.5），**不再属于否决项**，§十二 作废清单亦已同步移出。

若实验计入高利害成绩，建议**启用教师复核改分、对满分提交人工抽查**；真要根治伪造满分再启用服务端复算（需改变「步骤都在 HTML」这一前提）。**平台数据层已由 L2 沙箱根治，不再需要「优先上独立源」**；L3 独立源仅作为后续可选项（多租户 / 非可信教师上传），与高利害成绩无直接关系。

### 8.4 残余风险（必须随方案一起交付，不能隐去）

**A. 最高风险，v3 完全遗漏 —— 教师上传的 HTML 是同源可执行内容。**

> **阅读提示（最后检查补）**：以下能力表是 **v3.1 时点**的风险分析，用来说明「为什么必须改变信任边界」；**v3.2 正式架构下，custom 实验的教师 HTML 已改由 `sandbox` iframe 提供，表中「同源」前提不再成立**，这些能力绝大部分已被剥夺，见本节末尾与 §8.5。`courses` 存量自定义导图 / 演示页仍是同源（C39，本期不改）。

`lab_gate_page` 以 `text/html` 同源返回教师 HTML，学生用 `window.open(page_url, '_blank')` 打开（`LabList.vue:239`）。页面 JS 与平台主站**同源**，可直接读令牌、读非 HttpOnly cookie、发任意同源 API。v3 写的「保持 `connect-src 'self'`」既**不存在**（C26），也**防不住**这一条：`connect-src 'self'` 只拦外部域名，同域请求与本地读取都放行；`script-src 'self' 'unsafe-inline'` 更是显式允许页面内联脚本执行。

**能力边界（逐条对源码核过，用户 2026-11-05 明确表示此项不可接受）**：

| 能做到 | 依据 |
| --- | --- |
| 读 `access_token` + `refresh_token`；access 12h、**refresh 7 天可续期**（非"偷一次就过期"） | `store/user.js:22-23`、`api/request.js:15,34`、`settings.py:324-325` |
| **教师预览时读到教师令牌** → 改成绩、导出全班学情、增删课程；管理员预览范围更大 | `GET /api/labs/{id}/page/preview/` 同样是同源 `text/html` |
| 同源静默调全站 API，操作均记为「本人操作」，审计无异常 | JWT Bearer 由页面自行拼装 |
| `window.opener` 反向控制主站标签（reverse tabnabbing） | `LabList.vue:239` 无 `noopener`（C37） |
| `<form action="外域">` 把令牌 POST 外发 | 现成 CSP 串**无 `form-action`**（C36） |
| 动态插 `<base>` 劫持相对资源路径 | 现成 CSP 串**无 `base-uri`**（C36） |
| 页面内伪造「登录已过期」钓鱼、键盘记录 | 内联脚本被 `unsafe-inline` 允许 |

**这是存量风险，不是新模块引入的**：`courses/views.py:1158-1189` 对教师上传的自定义导图 / 演示 HTML 现在就是同源 `text/html` 返回，只挂了那串缺 `form-action` 的 CSP（C39）。新实验模块把它扩大为「每个学生进实验都执行一次」。

- 本期已写入的处置：S6 严格 CSP + `noopener` + `Referrer-Policy`；S8 静态扫描 + 源码确认 + sha256/上传者留痕 + 管理员告警。**这两层只降低发生概率、封住外发通道，不改变同源信任边界。**
- **v3.2 已选定 L2 并根治平台数据层风险**：教师 HTML 在 opaque origin 的 `sandbox` iframe 内，令牌存储抛异常、同源 API 变跨域、cookie 不可读、`window.opener` 受限。**A 风险至此闭环**。页面仍可渲染仿冒 UI，但用户 16:00 明确这是教师上传方责任，**本期不设计治理、不列为残余风险**；L0 的 CSP 与 L1 的静态扫描作为「封外发通道 / 防无心污染」的纵深防御继续保留，与钓鱼治理无关。

**B. 判分在学生浏览器，伪造满分不可根治。** §八 与对接说明已写明，S1–S8 均未改变这个上限。

**C. 链接可转发看答案。** L2 只改隔离、不涉及 URL 层，仍未解决（后续 B 档一次性兑换码）；票据绑 submission，转发不会刷到别人的分，但会泄露答案 / 允许代做。

**D. 票据运行期可见。** 学生在**自己会话的平台父页面**能看到自己本次票据（查看源码 / 网络面板）；**iframe 内完全读不到**（C25 已解决）。属用户已接受项。

**E. 多标签互挤与审计时间不准。** `bridge.py:15` `issue_token` 用 `update_or_create` 覆写票据，学生多标签进同一实验会互相挤掉；`models.py:203` 的 `issued_at` 是 `auto_now_add`，覆写时不更新。本期接受，B 档一并修。

### 8.5 A 风险专项：分层防护（**L2 已采纳，v3.2**）

**先说清一个判断**：上传的是**整份 HTML**，不是往页面里注入片段，等价于存储型 XSS 的「完全版」。单文件要求全部 JS 内联 → CSP 必须给 `script-src 'unsafe-inline'`，即信任页面全部脚本；静态扫描能挡字面量，挡不住 `window['local'+'Storage']` / `eval(atob(...))`。因此：

- **「检测并拦住恶意代码」做不到可靠**，只能挡无心事故；
- **「让恶意代码即使执行也拿不到东西」才能根治**，即改变信任边界。

| 层 | 措施 | 能防住 | 防不住 | 成本 / 影响面 |
| --- | --- | --- | --- | --- |
| **L0 立即做**（已纳入 S6） | 严格 CSP：`form-action 'none'` / `base-uri 'self'` / `object-src 'none'` / `frame-ancestors 'self'`；`window.open(..., 'noopener,noreferrer')`；`Referrer-Policy: no-referrer` | 表单外发、`<base>` 劫持、反向标签劫持、签名 URL 外泄、外链脚本 | **同源读令牌与同源 API 调用**（由 L2 解决）、仿冒 UI（不属本期范围） | 几行；顺带修 `courses` 存量缺口；预置实验零影响 |
| **L1 低成本**（已纳入 S8） | 上传静态扫描 + 命中告警 + 上传时源码二次确认 + sha256/上传者/可查源码 | **AI 生成代码夹带埋点、网上复制模板带后门**（最现实的两类来源）、账号被盗后的静默替换可被发现 | 定向混淆绕过；**教师本人恶意** | 服务端一个扫描函数 + 教师端一个确认页 |
| **L2 已采纳（v3.2）** | 仅 `page_source=custom` 启用 **`sandbox` iframe**（**不给 `allow-same-origin`**）：平台父页面持票据与 `LabBridge`，教师 HTML 在 opaque origin 的 iframe 内；iframe 内注入**无票据 shim**，`LabBridge.reportGrade()` 内部改 `parent.postMessage`，父页面校验 `event.source` 后上报 | **根治 A**：令牌存储抛异常、同源 API 变跨域、读不到 cookie、`window.opener` 受限；票据完全不进 iframe（**同时把 C25 做实**） | 报满分（已接受）；仿冒 UI 不属本期范围；`allow-forms` / `allow-modals` 需按页面需求放开 | 中：新增父页面模板 + 拆两套桥接 + `postMessage` 契约 + 接入说明 §五/§十 改写；**不需要 DNS / 独立源，7 个预置实验零改动** |
| **L3 最彻底** | 独立源子域托管教师 HTML（`labpages.<域名>`）+ `postMessage` | 同 L2，且不依赖 `event.origin === 'null'` 这种较脆弱的校验 | 同 L2 | 高：DNS 解析 + 证书 + nginx + 部署变更 |

**L2 的关键实现约束**（本期已采纳，实施时必须逐条满足）：

1. `sandbox` 属性**绝不能加 `allow-same-origin`**，否则 opaque origin 失效、沙箱被解除（浏览器会警告）；
2. opaque origin 下 `event.origin` 是字符串 `"null"`，**不能只靠它鉴权**，必须同时校验 `event.source === iframe.contentWindow`；
3. 父页面只接受一条 `lab:grade` 消息（一次性），按 §5.1 全链校验后才由父页面附 `X-Lab-Token` 上报；
4. iframe 内 shim 仍可用 `<script src>` 跨源加载平台桥接（经典脚本标签不受 CORS 约束），但**不能发带自定义头的同源 fetch**（触发预检）→ 分数只能走 `postMessage`；
5. 由此 §5.5 用 `lab-bridge-parent.js` + `lab-bridge-shim.js` 取代 v3.1 的单桥接 `lab-bridge-external.js`，**C25 的「票据不进教师页面」在 L2 下才真正成立**。

**用户口径与拍板结果（2026-11-05）**：残余风险 B/C/D（刷分、转发、票据运行期可见）明确接受（「成绩、转发这些都是小事」）；**A 不接受**。用户选择 **L2 `sandbox` iframe**。L0 / L1 / L2 全部纳入本期正式方案，§5.2 / §5.3 / §5.5 / §六 / §七 / §九～§十四 与对接说明均已按 L2 改齐；**L3 独立源留作后续可选**（若将来允许多租户/非可信教师上传，或需要连 `event.origin === 'null'` 这点也去掉，再上）。
